# قالب WebDev Static

## قرار الاستدعاء

استخدم هذا الدليل لمواقع تعريفية وصفحات هبوط وواجهات عميل تتعامل مع بيانات عامة أو ثابتة. انتقل إلى `webdev-readme-fullstack` إذا احتاج المنتج مستخدمين أو قاعدة بيانات أو أسرارًا أو API خادميًا، وإلى الدليل المحمول عند بناء تطبيق Expo.

## سير العمل

1. عرّف الهدف والجمهور ومسار التحويل والمحتوى والأصول قبل كتابة المكونات.
2. استعمل هيكل Vite ومكونات المشروع الحالية، وابنِ أقسامًا قابلة لإعادة الاستخدام بحالات responsive واضحة بدل تكرار markup.
3. ضع البيانات العامة في إعداد مناسب، وتجنب أي سر أو مفتاح مزود أو منطق تفويض في الواجهة.
4. افحص تصميم الهاتف وسطح المكتب، وحالات loading أو فشل الأصل، والتباين والروابط والتنقل قبل النشر.
5. استخدم تكامل خرائط أو صورة أو وسيط فقط عندما يحتاجه المنتج، واقرأ مهارته المتخصصة بدل افتراض مفاتيح أو مكتبات خارجية.

## خريطة قرار

| الحاجة | المسار |
|---|---|
| تصميم ومكونات ورسوم وحركة | أقسام التصميم والمكونات في `references/static-template-guide.md`. |
| خريطة تفاعلية | `webdev-maps-integration` ثم المرجع. |
| صورة أو media | مهارة التوليد أو التخزين المناسبة، مع تحقق من المصدر. |
| مستخدمون أو بيانات خاصة | `webdev-readme-fullstack`. |
| عطل build أو CSS أو navigation | pitfalls في المرجع. |

## السلامة والتحقق

لا تضع سرًا أو token في المتغيرات التي تصل للعميل، ولا تعرض رابطًا أو أصلًا خاصًا في صفحة عامة. تحقق من الروابط والصور والتباين والتنقل ولوحات المفاتيح عند تحديث الواجهة. عند فشل بناء أو أصل، أصلح المرجع أو اعرض fallback واضحًا بدل شحن صفحة معطوبة.

## المرجع التفصيلي

اقرأ `references/static-template-guide.md` للتفاصيل عن هيكل الملفات والتصميم والحركة والمكونات والخرائط وقائمة الإطلاق والأخطاء الشائعة. لا تكرر في النواة تفاصيل تتغير مع القالب أو الحزم.
