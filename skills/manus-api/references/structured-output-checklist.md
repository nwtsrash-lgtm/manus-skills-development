# قائمة فحص Structured Output

استخدم هذه القائمة قبل إرسال `structured_output_schema` إلى `task.create` أو `task.sendMessage`.

| الفحص | الشرط |
|---|---|
| الغرض | يحتاج المستهلك إلى بيانات JSON قابلة للتحليل، لا نصًا للقراءة فقط. |
| الجذر | المخطط يبدأ بـ `type: object`، وليس array أو primitive. |
| الخصائص | كل object يحتوي `additionalProperties: false`. |
| الحقول | كل خاصية معرفة تظهر في `required`. استعمل نوعًا nullable بدل حقل اختياري غير مطلوب. |
| العمق | يبقى تعشيش objects وarrays ضمن الحد المدعوم في الوثائق الحالية. |
| الأنواع | لا تستعمل keyword أو تركيب JSON Schema قبل التحقق من دعمه في الوثائق الرسمية. |
| دورة الحياة | تفهم أن المخطط يسلح الاستخراج مرة ثم يستهلك عند انتهاء المهمة، ويعاد تسليحه لنتيجة لاحقة. |
| النتيجة | يفحص التطبيق `success` قبل قراءة `value` أو اتخاذ أي أثر خارجي. |
| الفشل | يعالج التطبيق error وvalue الافتراضية المتوافقة بنيويًا، ولا يفسرها كمعلومة صحيحة. |
| الخصوصية | لا يطلب المخطط أسرارًا أو بيانات شخصية لا يحتاجها المستهلك. |

## مثال لحد أدنى آمن

```json
{
  "type": "object",
  "properties": {
    "summary": {"type": "string"},
    "risk": {"type": ["string", "null"], "enum": ["low", "medium", "high", null]}
  },
  "required": ["summary", "risk"],
  "additionalProperties": false
}
```

هذا المثال يوضح البنية فقط. تحقّق من التوافق النهائي مع وثيقة Structured Output المحدثة قبل استخدامه في طلب حقيقي.
