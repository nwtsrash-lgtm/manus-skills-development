# جمع دليل تشخيصي منقح

## الهدف

اجمع أقل دليل يثبت أو ينفي فرضية التشخيص. الدليل المفيد يوضح التوقيت والسياق ونوع الخطأ والحالة عند نقطة الانتقال؛ لا يحتاج عادةً إلى محتوى الطلب أو بيانات العميل أو بيانات الاعتماد.

## لا تطلب أو تعرض

لا تطلب أو تسجل أو تضع في تذكرة: مفاتيح API، رموز Bearer، كلمات المرور، محتوى ملفات `.env`، cookies، رؤوس Authorization، أرقام بطاقات، بيانات هوية، نص مستخدم كامل، أو نسخة قاعدة بيانات إنتاجية.

إذا كان السجل يحتوي قيمة حساسة، استبدلها بتصنيف ثابت مثل `[REDACTED_TOKEN]` أو بطول أو hash غير قابل للعكس عند الحاجة للمقارنة. لا تعتمد على الإخفاء المرئي وحده إذا كان النص الأصلي ما زال موجودًا في سجل أو لقطة شاشة.

## قالب دليل آمن

| الحقل | مثال آمن |
|---|---|
| النافذة الزمنية | `2026-08-13T10:42:00Z إلى 10:45:00Z` |
| البيئة | `staging` أو `production`، من دون اسم عميل أو رابط خاص |
| الإصدار | hash التزام أو رقم إصدار منشور |
| الحدث | `POST /orders أدى إلى 502`، من دون جسم الطلب |
| المعرّف | request ID أو correlation ID غير حساس |
| النتيجة | رمز الحالة، زمن الاستجابة، ونوع الاستثناء |
| السياق | فرق الإصدار أو اعتماد أو إعداد غير سري |

## نقاط الانتقال بين الأنظمة

عند تشخيص تدفق متعدد المكونات، سجّل لكل حد فاصل: هل وصل الحدث، هل تغيرت الحالة، وrequest ID أو زمن منقح يربط الطبقات. لا تنسخ الرسالة الخام بين الخدمات إذا كانت قد تحتوي على بيانات مستخدم. إن لم توجد طريقة ربط آمنة، أضف علامة ارتباط جديدة لا تحمل بيانات حساسة ثم أعد التجربة.

## قبل مشاركة الدليل

تحقق من عينة الدليل بحثًا عن أنماط الأسرار والبيانات الشخصية. إذا كان الشك قائمًا، لخّص السجل بدل نسخه. وثّق ما حُجب بحيث يفهم المراجع حدود الاستنتاج، ولا تتظاهر بأن الدليل كامل.
