# OAuth وإعادة التوجيه

## القاعدة الأساسية

يحمل العميل الأصل الفعلي عبر `window.location.origin` لأن الخادم لا يستطيع استنتاج واجهة النشر بدقة. لكن `origin` و`state` قيمتان يتحكم بهما العميل؛ لا تثق بهما وحدهما. استخدم تدفق القالب المضمن (`encodeOAuthState` و`decodeOAuthState` و`registerOAuthRoutes`) ولا تنشئ callback يدويًا موازيا له.

تحقق من أن origin يستخدم HTTPS في الإنتاج أو `localhost` في التطوير، وأنه يطابق قائمة origins مسموحة مهيأة للتطبيق قبل استعماله لإنشاء رابط خارجي أو تحويل. لا تعتمد على `req.host` أو env متقادم أو اسم مشروع لتخمين عنوان الواجهة.

## تسجيل الدخول

1. أنشئ nonce واحدًا فقط لحظة انتقال المستخدم الفعلي إلى صفحة تسجيل الدخول، وليس في كل render.
2. خزّن nonce في cookie host-only بوقت قصير، وضع نسخة مرتبطة داخل `state` باستخدام أدوات القالب. لا تسجل `state` أو code أو token.
3. في callback، حلل state بطريقة لا ترمي استثناءً، وقارن nonce مع cookie قبل استبدال code. عند غياب أو عدم تطابق أي قيمة، أعد 403 وتوقف؛ لا تستبدل code ثم تحاول التحقق لاحقًا.
4. امسح nonce بعد التحقق، وخزّن جلسة المستخدم في cookie بالخصائص الآمنة التي يوفرها القالب، ثم أعد التوجيه إلى مسار ثابت داخل التطبيق لا إلى URL من طلب المستخدم.
5. اشرح للمستخدم بوضوح إن كان المتصفح يحظر cookies اللازمة، ولا تعطل حماية nonce لتحويل التجربة إلى «تعمل».

## روابط الدعوة وMagic Links

اطلب origin من الواجهة عند إنشاء رابط، ثم حلله بـ `URL` وتحقق من البروتوكول والمضيف مقابل القائمة المسموحة قبل تركيب المسار والرمز. لا تعكس origin أو return URL عشوائيًا في البريد أو redirect. اجعل الرمز قصير العمر، أحادي الاستخدام عند الحاجة، ومقترنًا بالسجل والصلاحية التي أنشأته.

## حالات الفشل والتحقق

اختبر origin صالحًا وآخر غير مسموح، nonce صحيحًا وآخر مفقودًا أو غير مطابق، state مشوهًا، code مفقودًا، وcookie محجوبة، ورابط دعوة منتهٍ أو مستخدم. تأكد أن error لا يكشف code أو token، وأن callback لا يبدل code إذا فشل التحقق، وأن إعادة التوجيه النهائية لا يمكن تحويلها إلى موقع خارجي.
