# طلب موافقة إعداد الربط التلقائي

## الهدف

إعداد نشر تلقائي وآمن بعد كل تغيير معتمد في المستودع، مع نسخ احتياطي مستقل لبيانات التطبيق. بعد الإعداد لا يتطلب النشر اليومي أو النسخ الدوري تدخلاً يدوياً.

## ما سيتم إنشاؤه أو تغييره

| الفئة | العنصر | الغرض | الصلاحية/الأثر |
|---|---|---|---|
| GitHub | [workflow أو Git App] | تشغيل اختبار ثم نشر عند `push` إلى [الفرع] | قراءة الكود وتنفيذ workflow فقط. |
| GitHub | [repository/environment secrets] | حفظ مفتاح النشر وknown hosts إن لزم | غير ظاهر في السجلات عند الاستخدام الصحيح. |
| الخادم | [مستخدم deployer/مفتاح SSH] | تنفيذ release محدود | لا يستخدم root تفاعلياً؛ يسمح بأمر release فقط. |
| التخزين | [R2/B2/OCI bucket] | replication ونسخ احتياطية | prefix محدود ومفتاح منفصل للحذف. |
| الشبكة | [Tailscale/بوابة هوية/HTTPS] | تقييد الوصول إلى التطبيق | لا يفتح التطبيق للإنترنت العام إلا إذا ذُكر صراحة. |
| الجدولة | [systemd timer/cron] | النسخ اليومي وفحص الاستعادة | تشغيل محلي محدد ومراقب. |

## ما لا سيتم فعله

لن يتم إدخال بطاقة أو قبول دفع أو ترقية خطة. لن يتم نشر التطبيق للعامة أو إرسال webhook إنتاجي أو تعديل البيانات الحية دون موافقة منفصلة. لن تُرفع أسرار أو قواعد SQLite الإنتاجية إلى Git.

## اختبارات القبول

- [ ] ينجح workflow لاختبار commit ويعرض SHA المنشور.
- [ ] لا تحذف إعادة النشر مجلد البيانات الدائم.
- [ ] ينجح restore من النسخة القريبة والنسخة المستقلة في بيئة اختبار.
- [ ] لا تظهر الأسرار في سجلات GitHub أو الخادم.
- [ ] يمكن إيقاف الأتمتة بتعطيل workflow أو مفتاح deploy.
