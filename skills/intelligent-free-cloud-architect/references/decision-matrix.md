# مصفوفة قرار الخدمات المجانية

## تصنيف العرض قبل المقارنة

| التصنيف | التعريف | كيف يُعرض للمستخدم |
|---|---|---|
| مجاني دائم ضمن حد | سعة شهرية أو مورد لا ينتهي ما دامت الحدود محترمة. | مرشح حقيقي، مع ذكر الحد وسياسة الإفراط. |
| تجربة أو رصيد | ينتهي بوقت أو رصيد أو بتحويل الحساب. | لا تقدمه كحل دائم؛ يصلح للتجربة فقط. |
| طبقة تحكم مجانية | واجهة أو orchestrator مجاني، بينما الخادم أو التخزين مدفوع. | افصل تكلفة التطبيق عن تكلفة لوحة التحكم. |
| مفتوح المصدر ذاتي الاستضافة | البرنامج مجاني لكن يحتاج خادماً وصيانة. | اذكر تكلفة/مصدر الخادم صراحة. |
| مجاني مع نوم أو حذف | خدمة مجانية لكنها توقف العملية أو تمسح القرص/القاعدة. | اقبلها فقط للمواقع التجريبية عديمة الحالة. |

## حواجز الاستبعاد

استبعد المرشح عند تحقق أحد الآتي ما لم يغير المستخدم المتطلب صراحة:

- الذاكرة أقل من أعلى ذروة مقاسة مع هامش 50%.
- القرص مؤقت وقاعدة البيانات أو uploads يجب أن تبقى.
- التطبيق يحتاج Docker أو متصفح أو binary غير مسموح.
- توجد مهام طويلة أو webhook لكن الخدمة تنام أو تقطع التنفيذ.
- التطبيق يحتاج SQLite متعدد الملفات لكن المنصة لا تدعم volume دائم.
- الوصول العام مفروض بينما البيانات لا ينبغي كشفها ولا تتوافر طبقة حماية مناسبة.
- العرض تجريبي فقط بينما المطلوب تشغيل طويل الأجل.

## نموذج تنقيط بعد الحواجز

امنح لكل معيار 0–5، ثم احسب الوزن. لا تنقّط مرشحاً مستبعداً.

| المعيار | الوزن الافتراضي | معنى الدرجة 5 |
|---|---:|---|
| استمرارية البيانات | 35 | قرص/قاعدة دائمة، نسخة مستقلة، واستعادة قابلة للاختبار. |
| ملاءمة الموارد | 20 | CPU/RAM/قرص كافية مع هامش نمو. |
| الأمان | 15 | secrets، وصول خاص، HTTPS، أقل صلاحيات، ونسخ قابلة للتشفير. |
| سهولة التشغيل | 15 | نشر متكرر واضح، سجلات، مراقبة، وrollback ممكن. |
| Git والنشر | 10 | ربط Git/Webhook موثق وsecrets منفصلة. |
| هامش النمو | 5 | يمكن تطويره بلا إعادة بناء عاجلة. |

استخدم المعادلة: `النتيجة = مجموع (الدرجة ÷ 5 × الوزن)`.

## اختبار «المجاني الحقيقي»

قبل الحكم النهائي، أجب بنعم/لا مع مصدر:

1. هل يبقى المورد متاحاً بعد 30 و90 يوماً من دون دفع؟
2. هل تتطلب المنصة بطاقة أو اشتراكاً مدفوعاً فقط لتفعيل المورد؟
3. هل يمكن أن تتكبد رسوم تلقائياً عند تجاوز حد؟ وما هو إجراء الحماية؟
4. هل تُحذف البيانات عند sleep أو redeploy أو عدم نشاط؟
5. هل تعمل المنطقة المطلوبة أو توجد سعة فعلية للمورد المجاني؟
6. هل سيتجاوز workload حدود عمليات API أو egress حتى إن كانت سعة التخزين قليلة؟
7. هل يمكنك استعادة النظام إذا أُغلق الحساب أو فُقد الخادم؟

إذا كانت الإجابة غير موثقة، صنفها **غير مؤكدة** لا **آمنة**.
