# خلفية WebDev Mobile

## قرار الاستدعاء

استخدم هذا الدليل عندما تحتاج الشاشة المحمولة إلى بيانات مستخدم أو قاعدة بيانات أو إجراء محمي أو خدمة خارجية. اقرأ دليل Mobile للهيكلة والشاشات، واستخدم الدليل المتخصص لأي تكامل بعد تحديد أن الاستدعاء يجب أن يبقى خادميًا.

## سير العمل

1. حدّد مالك البيانات ونموذجها والصلاحيات قبل كتابة route أو procedure.
2. عرّف أو عدّل schema ثم طبّق migration مناسبًا، وأنشئ query أو mutation بمدخلات متحققة وأنواع متسقة.
3. تحقق من جلسة المستخدم وملكية السجل في الخادم لكل قراءة أو كتابة خاصة، ثم اعرض للعميل مخرجًا محدودًا يحتاجه فقط.
4. ضع LLM والصوت والصورة والتخزين ومفاتيح المزودين داخل الخادم، مع حدود حجم ووقت وإعادة محاولة مضبوطة.
5. اختبر نجاح العملية، إدخالًا غير صالح، مستخدمًا غير مفوض، فشل تبعية، وتحديثًا متزامنًا قبل ربطها بالشاشة.

## خريطة قرار

| الحاجة | البداية |
|---|---|
| حساب أو جلسة أو تسجيل دخول | قسم Authentication في `references/template-guide.md`. |
| بيانات ومخطط ومهاجرات | قسم Database ثم tRPC في المرجع. |
| نموذج أو صوت أو صورة أو ملف | مهارة التكامل الخاصة، ثم قسم القدرات في المرجع. |
| حدود أو أسرار أو فشل API | Environment Variables وTesting وTroubleshooting في المرجع. |
| شاشة فقط | ارجع إلى `webdev-readme-mobile`. |

## السلامة والتحقق

لا تثق بمعرف مستخدم أو role أو سعر أو عنوان ملف من العميل. لا تكشف أسرار البيئة أو استجابة المزود الكاملة في logs أو أخطاء العميل. اجعل migrations قابلة للمراجعة، ولا تنفذ أثرًا خارجيًا أو عملية حذف عند فشل التحقق أو بلا تفويض صريح. عند فشل API، أعد خطأً منقحًا قابلًا للتصرف وسجل request context غير الحساس.

## المرجع التفصيلي

اقرأ `references/template-guide.md` للتفاصيل الدقيقة الخاصة بالمصادقة وDrizzle وtRPC والتكاملات والاختبار والملفات الأساسية. لا تكرر هذه التفاصيل المتغيرة في النواة.
