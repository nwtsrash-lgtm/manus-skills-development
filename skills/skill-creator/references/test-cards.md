# بطاقات اختبار السلوك

استخدم بطاقة سلوك لتثبت أن المهارة تستدعى في السياق الصحيح وتتصرف بأمان عندما يفشل شرط أو تكون خارج نطاقها. احفظ البطاقة بصيغة JSON في حزمة الاختبار أو استخدم البنية نفسها عند اختبار مهارة مستقلة.

## الحد الأدنى

| مستوى المخاطر | الحد الأدنى | التوزيع المطلوب |
|---|---:|---|
| عادي | 3 حالات | استدعاء صحيح، عدم استدعاء، فشل أو أمان. |
| مرتفع | 6 حالات | حالتا استدعاء صحيحتان، حالتا عدم استدعاء، وحالتا فشل أو أمان. |

تعد مهارة عالية المخاطر إذا كانت تغير إعدادات، أو تتعامل مع API أو OAuth أو أسرار أو تخزين أو جدولة أو نشر أو آثار خارجية.

## بنية الحالة

استخدم الحقول التالية: `id` معرف ثابت، و`kind` من `positive` أو `negative` أو `failure` أو `safety`، و`prompt` طلب واقعي، و`should_invoke` قيمة منطقية، و`expected_outcome` نتيجة يمكن مراجعتها. اجعل الطلب محددًا بما يكفي للتمييز بين المهارات المتجاورة.

## أمثلة موجزة

```json
{
  "id": "create-repeatable-report",
  "kind": "positive",
  "prompt": "أنشئ مهارة تبني تقرير تدقيق أسبوعي من مصادر ثابتة.",
  "should_invoke": true,
  "expected_outcome": "تحدد العملية المتكررة والموارد والاختبارات قبل بناء المهارة."
}
```

```json
{
  "id": "single-output",
  "kind": "negative",
  "prompt": "اكتب ملخصًا لاجتماع اليوم.",
  "should_invoke": false,
  "expected_outcome": "ينفذ الملخص مباشرة ولا ينشئ مهارة جديدة."
}
```

لا تضع مفاتيح فعلية أو بيانات عميل أو نتائج حساسة داخل بطاقات الاختبار. اختبر الحدود والسلوك المتوقع لا تشابه الصياغة فقط.
