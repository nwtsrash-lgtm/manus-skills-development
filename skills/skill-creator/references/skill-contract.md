# عقد تصميم المهارة

استخدم هذا العقد عند إنشاء مهارة جديدة أو عند مراجعة مهارة قبل اعتمادها. لا يلزم وضع كل الحقول في Frontmatter؛ الغرض هو إثبات أن التعليمات تغطيها حيث تكون مفيدة.

| العنصر | الدليل المطلوب |
|---|---|
| الاسم | معرف صغير بحروف إنجليزية صغيرة وشرطات، ويطابق المجلد. |
| الوصف | يوضح القدرة وحالات الاستدعاء، ولا يكتفي باسم المجال. |
| النطاق | أمثلة لما يجب أن تستدعيه المهارة وما لا يجب أن تستدعيه. |
| المدخلات | أقل معلومات أو ملفات أو موافقات لازمة للبدء. |
| سير العمل | خطوات مرتبة أو شجرة قرار، مع نقاط توقف عند نقص الدليل. |
| الموارد | مبرر لكل مرجع أو برنامج أو قالب، مع تجنب التكرار. |
| السلامة | تصرف واضح عند الأسرار أو البيانات الحساسة أو الأثر الخارجي أو الفشل. |
| التحقق | اختبار مخرج أو تشغيل أو بطاقة سلوك تبين ما يعد نجاحًا. |
| الحداثة | مصدر رسمي أو تاريخ تحقق عندما تتضمن المهارة حقائق متغيرة عن API أو منصة أو حدود خدمة. |

## درجات الحرية

استخدم تعليمات نصية عامة للمسائل التي تختلف حلولها باختلاف السياق. استخدم نموذجًا أو شبه كود للأنماط المتكررة التي تحتاج تعديلًا محدودًا. استخدم برنامجًا ثابتًا قليل المعاملات فقط للعمليات الحساسة أو الحتمية؛ واختبره على حالة تمثيلية قبل التسليم.

## الإفصاح التدريجي

أبقِ القرار وسير العمل الأساسيين في `SKILL.md`. انقل البدائل المتخصصة والجداول الطويلة والمراجع المتغيرة إلى `references/` واربطها بجملة تبين متى يجب قراءتها. لا تنقل خطوة أساسية إلى مرجع بحيث يتعذر تنفيذ الاستخدام الشائع من النواة.
